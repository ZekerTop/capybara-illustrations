# Capybara Illustrations

## 核心定位

把创作者内容里的观点、流程、状态、对比和隐喻，转成有松弛感、情绪稳定感和一点幽默感的卡皮巴拉（水豚）插图。

这不是火柴人、儿童贴纸、固定吉祥物或某个角色 IP。默认主体必须先通过卡皮巴拉形体锁定：低矮横向桶形或豆形身体、身体明显大于头、头接在身体前端、小圆耳位于头顶偏后、眼睛小而靠上、鼻梁长且鼻口部宽钝、短小爪子贴近身体、稳定表情、慢悠悠姿态。它可以可爱，但不要幼稚；可以有趣，但不要变成表情包。

生成提示词里必须把“像卡皮巴拉”写成可检查的形体要求，而不是只写 cute capybara。即使遮住文字标签，主体轮廓也要能被看成卡皮巴拉，而不是普通小熊、仓鼠、狗或未知萌物。

用户不需要重复写基础视觉要求。只要用户给出观点、文章、场景或想表达的意思，就按默认规则生成：`16:9` 画幅、白底或透明白底、黑色线稿、卡皮巴拉主体、默认柔和暖棕色和一个克制点缀色、可读情绪、表达性短标注。只有当用户明确指定画幅、背景、颜色、文字密度或模式时，才覆盖默认规则。

默认追求表现力，不追求“字越少越好”。除非用户明确要求“无文字”“不要标注”或场景必须避开本地化文字，否则默认加入能帮助理解的短标注：短标题或 punchline、关键物件标签、状态词、动作词或对比词。文字必须增强情绪、对比、节奏或记忆点；不要变成段落说明、满屏标注或 PPT 模板。

## 硬性边界

- 不把卡皮巴拉画成火柴人、仓鼠、熊、狗、猫或未知萌物。
- 不使用熊式圆头、仓鼠式大腮帮、狗猫式尖鼻或大耳朵来替代卡皮巴拉。
- 不画固定品牌吉祥物、表情包角色、儿童贴纸或高识别度角色 IP。
- 不复刻任何已知创作者、插画师、品牌、IP 或公开示例的构图与语气。
- 不把图做成复杂 PPT 信息图、正式架构图、商业 KV、3D、拟物或照片。
- 不让卡皮巴拉只是站桩装饰。它必须承担动作、情绪或观点。
- 不默认纯黑白。用户没指定时，使用轻量彩色版；用户指定 `mono` 或黑白时才切换。

## 工作流

### 1. 读内容，找视觉锚点

先读用户给的文章、Markdown、文档、主题、场景或观点。提炼：

- 核心观点
- 读者卡住的地方
- 能改善阅读观感和节奏的停顿点
- 适合被画出来的动作、状态、对比或路径
- 能用卡皮巴拉表达“松弛、稳定、慢下来、下一步”的地方
- 不适合配图、只适合文字解释的部分

不要平均配图。优先选真正帮助理解或传播的视觉锚点：关键判断、前后对比、步骤转换、输入输出、常见错误、决策分岔、情绪转折、成果展示。

### 2. 先出 shot list

除非用户明确说“直接生成 / 现在生图 / 不要规划”，否则先输出 shot list。每张图写清楚：

- 放置位置或使用渠道；文章类必须写到章节名、段落后或某句之后
- 画幅；未指定时默认 `16:9`
- 图的主题
- 核心意思
- 构图模式
- 卡皮巴拉在做什么
- 卡皮巴拉是什么情绪
- 主要元素
- 建议标注；默认写出可直接放进图里的短标题、物件标签和状态词，不能只写“少量标注”
- 优先级

默认 3-6 张候选。短内容可以 0-2 张；长文、课程或轮播可扩到 8-10 张，但必须说明每张的用途。不要为了凑数量而推荐装饰图。

文章类请求优先按规划处理。用户说“给这篇文章生成插图”“为文章配图”“合理性生成插图”“合理生成插图”“进行合理性生成插图”时，如果没有明确写“直接生成 / 现在生图 / 不要规划”，先输出带插入位置的 shot list，不要立刻调用图像生成。文章 + 生成插图 不等于 直接生成。

每次输出 shot list 后，必须追加 `下一步` 区块，告诉用户现在可以直接回复什么。至少给出：

- 推荐先生成哪一张，以及一句原因。
- 可直接复制的回复命令，例如 `生成 #1`、`生成 #1 和 #2`、`调整 #1：用 mono，不要标题`、`先不生成，重新检查插图位置`。
- 如果不建议加图，给出 `不生成，保持文章原样` 或 `重新检查另一版文章` 这类下一步。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 直接画”，直接为每张图单独调用图像生成工具。不要把多张图拼在一张里，除非用户要求轮播总览或分镜板。

如果上下文是文章配图，只有两种情况可以直接生成：用户已经选择了 shot list 编号，例如 `生成 #1`、`生成 #1 和 #2`；或用户明确说 `直接生成`、`现在生图`、`不要规划`。生成后仍必须返回插入位置。

每张图只表达一个核心意思。提示词必须包含：

- 目标渠道和画幅；用户未指定时使用 `16:9`
- 卡皮巴拉主体，且默认作为画面主角
- 形体锁定：低矮横向桶形身体、身体大于头、头在身体前端、小圆耳靠后、小黑眼靠上、长而宽钝的鼻口部、短小爪子贴近身体
- 反例禁令：不要熊式圆头、仓鼠式鼓腮、狗猫式尖鼻、大头吉祥物或泛化可爱动物
- 用简单表情、头部角度、爪子动作和身体姿态把情绪读清楚
- 简洁黑色线稿
- 默认柔和暖棕色主体和一个克制点缀色；用户指定 `mono` 时只用黑白
- 大量留白
- 默认加入表达性短标注：1 个短标题或 punchline，2-5 个物件/状态/动作标签；只有用户明确要求无文字或纯图时才生成无文字版
- 物件和路径要有足够说明，避免读者只能猜画面含义；标注要短、有趣、能服务观点
- 禁止第三方 IP、固定角色、特定作者风格、复杂 PPT 感

### 4. 文章观感优化配图

如果用户要求“给文章找插图位置并同时生成图片 / 一键配图 / 直接给插入位置和图片”，目标是让文章观感更好，而不是塞满插图。不要停在 shot list。先快速完成视觉锚点和阅读节奏筛选，再为 `P0` 和明确能改善阅读体验的 `P1` 图片逐张生成。如果没有合适位置，明确说不建议强行加图。

每张图交付时必须包含：

- 具体插入位置：章节名，或插在某段/某句之后；插入位置必须写到段落或句子之后，不能只写“文章中部”。
- 生成后的图片展示；如果当前环境不能生图，改为给出可直接用于生图的完整提示词，并明确说明未生成。
- Markdown 插入代码，例如 `![图片说明](./assets/article-slug-illustrations/01-topic.png)`。
- 一句话说明这张图如何改善阅读观感、节奏或理解。

### 5. 模式开关

默认使用 `soft-color`：

- 白底
- 黑色线稿
- 柔和暖棕色卡皮巴拉主体
- 一个克制点缀色
- 短标注

当用户写 `mono`、`黑白`、`不要颜色`、`白底黑线` 时，切换到纯黑白线稿：

- 白底
- 黑色线稿
- 不使用主体填色
- 可以保留文字标注

不要让用户为了基础效果手写长要求。模式词只是覆盖默认值的快捷开关。

### 6. 检查与迭代

生成后读取 `references/qa-checklist.md`。如果出现以下问题，重生成或局部编辑：

- 看不出是卡皮巴拉
- 遮住文字后只像普通萌宠、仓鼠、熊或大头吉祥物
- 缺少低矮横向桶形身体、长宽钝鼻口部、小圆耳靠后等关键形体
- 太像普通萌宠、仓鼠、熊或固定吉祥物
- 表情和动作没有体现松弛、稳定或观点情绪
- 文字太少，导致物件和状态需要猜
- 文字太多，变成 PPT 或说明书
- 画面只是可爱装饰，没有帮助表达观点
- 元素太满
- 颜色太花
- 可被看出在模仿某个现成风格

### 7. 保存交付

如果用户在 workspace 内工作，把最终图保存到：

```text
assets/<project-or-article-slug>-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

策略输出要短、可执行。生成后的交付包含：

- 生成了几张
- 每张图适合放在哪里
- 每张图的 Markdown 插入代码
- 保存路径
- 是否有需要重画、加字、删字或切换 `mono` 的图

不要讲风格理论。创作者要的是能马上用的图。
